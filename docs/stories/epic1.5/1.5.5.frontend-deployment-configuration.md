# Story 1.5.5: 前端部署与域名配置

## Status
Draft

## Story
**作为** 系统部署者，
**我希望** 完成前端应用的部署和域名配置，
**以便** 用户可以通过HTTPS安全访问LiVin Matrix前端应用。

## Acceptance Criteria

1. **GitHub Pages部署配置完成**
   - GitHub Pages在Repository Settings中启用
   - 前端应用成功构建并部署到GitHub Pages
   - GitHub Pages站点可以通过HTTPS访问
   - 自动部署工作流正常触发
   - 部署状态可以在Actions页面查看

2. **前端生产环境配置完成**
   - 生产环境变量正确配置指向后端API
   - Auth0集成在生产环境正常工作
   - 前端应用可以成功连接到AWS后端服务
   - 生产构建优化设置生效
   - PWA配置和缓存策略正确应用

3. **自定义域名配置完成（可选）**
   - 自定义域名DNS记录配置正确
   - 域名CNAME记录指向GitHub Pages
   - HTTPS证书通过Let's Encrypt自动获取
   - 域名强制HTTPS重定向生效
   - 子域名和www重定向配置正确

4. **CDN和性能优化配置**
   - 静态资源缓存策略配置正确
   - 图片和资源压缩优化生效
   - 前端资源通过CDN分发
   - 页面加载性能达到要求
   - SEO基础配置完成

5. **前后端集成验证完成**
   - 前端可以成功调用后端API
   - Auth0登录流程在生产环境正常工作
   - 跨域(CORS)配置正确无错误
   - 用户数据读写功能正常
   - 错误处理和用户反馈正常显示

// AuthContext配置验证
const domain = import.meta.env.VITE_AUTH0_DOMAIN;
const clientId = import.meta.env.VITE_AUTH0_CLIENT_ID;
const audience = import.meta.env.VITE_AUTH0_AUDIENCE;

  throw new Error('Auth0 configuration missing');
}

### 域名配置策略
**来源**: [Source: deploy/scripts/github-pages-setup.sh]

**GitHub Pages域名配置**:
1. **默认域名**: `your-username.github.io/repository-name`
2. **自定义域名配置**:
   - DNS CNAME记录：`www.your-domain.com` → `your-username.github.io`
   - GitHub Pages设置中添加自定义域名
   - 启用"Enforce HTTPS"强制SSL

**DNS配置示例**:
```dns
# A记录（根域名）
@ IN A 185.199.108.153
@ IN A 185.199.109.153
@ IN A 185.199.110.153
@ IN A 185.199.111.153

# CNAME记录（www子域名）
www IN CNAME your-username.github.io.
```
