# Story 1.5.7: AWS基础设施部署

## Status
Ready

## 你的目标
在AWS云环境中部署生产级基础设施，让应用能在云端稳定运行。

## 你需要做的关键操作

### 🔧 AWS账号和权限准备（你必须亲自完成）
- [ ] **AWS账号配置**
  - 确保拥有AWS账号并完成实名认证
  - 配置AWS CLI：`aws configure`
  - 验证权限：`aws sts get-caller-identity`

- [ ] **免费层资源确认**
  - 检查免费层剩余配额
  - 设置成本警报（建议$5/月）
  - 了解即将创建的资源成本

### 🏗️ 基础设施部署（你亲自执行）
- [ ] **创建VPC网络**
  ```bash
  # 使用已准备的脚本部署
  ./deploy/scripts/aws-setup.sh vpc
  ```

- [ ] **部署EKS集群**
  ```bash
  # 创建Kubernetes集群（需要15-20分钟）
  eksctl create cluster -f deploy/aws/eks-cluster.yaml

  # 配置kubectl访问
  aws eks update-kubeconfig --name livin-matrix-cluster

  # 验证集群
  kubectl get nodes
  ```

- [ ] **创建RDS数据库**
  ```bash
  # 部署PostgreSQL数据库
  ./deploy/scripts/rds-setup.sh

  # 等待数据库可用（约10-15分钟）
  aws rds describe-db-instances --db-instance-identifier livin-matrix-db
  ```

### 🔗 应用部署和配置（你亲自验证）
- [ ] **部署应用到Kubernetes**
  ```bash
  # 应用Kubernetes配置
  kubectl apply -f deploy/aws/

  # 检查Pod状态
  kubectl get pods -n livin-matrix

  # 查看服务状态
  kubectl get services -n livin-matrix
  ```

- [ ] **配置负载均衡器**
  ```bash
  # 等待ALB创建完成
  kubectl get ingress -n livin-matrix

  # 获取ALB地址
  kubectl describe ingress -n livin-matrix
  ```

### 🧪 部署验证测试（你亲自测试）
- [ ] **健康检查验证**
  ```bash
  # 测试后端API健康
  curl https://your-alb-domain.com/api/v1/health

  # 测试数据库连接
  curl https://your-alb-domain.com/api/v1/health/db
  ```

- [ ] **端到端功能测试**
  - 通过ALB地址访问应用
  - 测试GitHub OAuth登录
  - 验证数据能正确保存到RDS
  - 确认所有功能正常工作

## 技术背景信息

### AWS架构概览
- **网络**: VPC + 公有/私有子网
- **计算**: EKS Kubernetes集群 (t3.micro节点)
- **数据库**: RDS PostgreSQL (db.t3.micro)
- **负载均衡**: Application Load Balancer (ALB)
- **监控**: CloudWatch + 成本警报

### 免费层资源配置
- EKS控制平面: 免费
- EC2 t3.micro: 750小时/月
- RDS db.t3.micro: 750小时/月
- ALB: 750小时/月
- 数据传输: 15GB出站/月

### 部署时间预估
- VPC创建: 2-5分钟
- EKS集群: 15-20分钟
- RDS数据库: 10-15分钟
- 应用部署: 5-10分钟
- 总计: 约40-50分钟

### 常见问题排查
如遇到问题，可向dev agent询问：
- 资源创建失败：检查配额和权限
- 集群连接失败：检查kubectl配置
- 应用启动失败：检查Pod日志和资源限制
