## 用户故事

**作为** 开发者
**我想要** 标准化的服务启动和管理脚本（既能一键启动所有服务，也能单独启动各项服务）
**以便** 能够灵活、稳定地管理开发环境，根据不同开发需求启动相应的服务组合

## 业务价值

- **提升开发效率**: 一键启动全部服务或根据需要启动部分服务
- **灵活的开发模式**: 支持仅数据库、仅前端、仅后端等不同开发场景
- **减少环境问题**: 标准化启动流程避免环境不一致
- **改善开发体验**: 自动处理端口冲突和服务依赖关系

## 问题陈述

### 当前痛点

1. **进程管理不稳定**: 命令行会话依赖导致服务在超时后终止
2. **启动流程不标准化**: 每次手动启动，环境可能不一致
3. **网络配置问题**: macOS本地网络配置影响端口访问
4. **缺乏故障恢复机制**: 服务停止后需要手动重启
5. **Agent启动服务不规范**: 无论是直接script还是docker环境都缺乏标准化

### 业务影响

- 开发效率降低，需要频繁手动干预
- 环境不一致导致的调试困难
- 服务不稳定影响开发体验

- **集成对象**: Docker Compose 多服务架构 (前端、后端、PostgreSQL、Redis)
- **技术栈**: Node.js + FastAPI + PostgreSQL + Docker + Nginx
- **现有模式**: 通过 package.json scripts 和 docker-compose 简单启动
- **接触点**: Docker 容器管理、端口映射、环境变量配置、进程监控

- `package.json` 中的基础启动命令
