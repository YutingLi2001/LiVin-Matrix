# Story 1.5.3: GitHub CI/CD环境配置

## Status
Draft

## Story
**作为** 系统部署者，
**我希望** 完成GitHub Secrets和CI/CD环境配置，
**以便** 启用LiVin Matrix项目的自动化测试、构建和部署流水线。

## Acceptance Criteria

1. **GitHub Repository Secrets配置完成**
   - 所有必需的AWS凭据已安全添加到GitHub Secrets
   - Auth0配置变量已正确设置
   - Docker Hub或AWS ECR凭据已配置
   - 通知服务密钥已添加（如Slack Webhook）
   - 测试用数据库连接字符串已配置

2. **前端CI/CD环境变量配置**
   - 前端生产环境变量已配置
   - GitHub Pages部署设置已启用
   - 自定义域名配置已完成（如适用）
   - 环境特定的API端点配置完成
   - 构建优化配置已设置

3. **后端CI/CD环境配置**
   - 生产数据库连接配置完成
   - Kubernetes配置文件环境变量已设置
   - Docker镜像构建标签策略已配置
   - 健康检查端点配置已验证
   - 容器注册表推送权限已配置

4. **CI/CD工作流触发条件验证**
   - 代码推送到main分支触发完整流水线
   - Pull Request触发测试和构建流程
   - 手动触发工作流功能正常
   - 路径过滤规则正确工作（前端/后端分离）
   - 工作流状态徽章正常显示

5. **自动化测试环境配置验证**
   - 测试数据库服务正常启动
   - 代码覆盖率报告正常生成和上传
   - 代码质量检查（ESLint、Black、Flake8）通过
   - 安全扫描配置正常工作
   - 测试结果通知正常发送

### GitHub Actions工作流架构
**来源**: [Source: deploy/CICD_GUIDE.md#工作流详解]

**前端工作流流程**:
```yaml
代码提交 → 测试 → 构建 → 部署到 GitHub Pages
    ↓        ↓      ↓           ↓
  Checkout  Jest   Docker   GitHub Pages部署
   代码    测试    镜像       静态网站托管
          ESLint  构建
         覆盖率
```

**后端工作流流程**:
```yaml
代码提交 → 测试 → 构建 → 部署到 Staging → 验证
    ↓        ↓      ↓        ↓           ↓
  Checkout  pytest Docker  K3s部署    健康检查
   代码     测试   镜像    滚动更新     烟雾测试
          Black   构建
          Flake8
         覆盖率
```

### 必需的GitHub Secrets清单
**来源**: [Source: deploy/CICD_GUIDE.md#环境配置]

**AWS相关Secrets**:
```bash
AWS_ACCESS_KEY_ID=AKIA...
AWS_SECRET_ACCESS_KEY=...
AWS_DEFAULT_REGION=us-east-1
```

**Auth0相关Secrets**:
```bash
AUTH0_DOMAIN=your-tenant.auth0.com
AUTH0_CLIENT_ID=...
AUTH0_CLIENT_SECRET=...
AUTH0_AUDIENCE=https://api.livin-matrix.example.com
```

**容器注册表Secrets**:
```bash
DOCKER_USERNAME=your-docker-username
DOCKER_PASSWORD=your-docker-password
# 或者使用AWS ECR
AWS_ECR_REPOSITORY_URI=123456789012.dkr.ecr.us-east-1.amazonaws.com/livin-matrix
```

**可选通知Secrets**:
```bash
SLACK_WEBHOOK_URL=https://hooks.slack.com/services/...
CODECOV_TOKEN=... # 如果使用Codecov
```

### 环境变量配置策略
**来源**: [Source: docs/stories/1.3.auth0-user-authentication-integration.md#环境变量配置]

**前端环境变量（Vite项目）**:
```bash
# 开发环境
VITE_AUTH0_DOMAIN=your-tenant.auth0.com
VITE_AUTH0_CLIENT_ID=your-client-id
VITE_AUTH0_AUDIENCE=https://api.livin-matrix.example.com
VITE_API_BASE_URL=http://localhost:8000

# 生产环境
VITE_API_BASE_URL=https://api.livin-matrix.example.com
```

**后端环境变量**:
```bash
# 开发环境
DATABASE_URL=postgresql://postgres:password@localhost:5432/livin_matrix_dev
SECRET_KEY=dev-secret-key

# 生产环境
DATABASE_URL=postgresql://postgres:password@rds-endpoint:5432/livin_matrix_prod
SECRET_KEY=super-secure-production-key
```

### CI/CD质量门控配置
**来源**: [Source: deploy/CICD_GUIDE.md#质量门控]

**代码质量标准**:
- **前端**: ESLint检查通过率100%，测试覆盖率≥80%
- **后端**: Black格式化检查通过，Flake8检查通过，pytest覆盖率≥80%

**性能要求**:

**安全检查**:

- 容器镜像安全扫描

### 工作流触发策略
**来源**: [Source: .github/workflows/frontend-ci.yml, .github/workflows/backend-ci.yml]

**自动触发条件**:
- Push到main分支：触发完整CI/CD流程
- Pull Request：只执行测试和构建，不部署
- 路径过滤：前端变更(`frontend/**`)只触发前端流水线

**手动触发**:
- GitHub Actions页面手动触发
- 支持参数选择（环境、分支等）
