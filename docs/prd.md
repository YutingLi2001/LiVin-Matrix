# LiVin Matrix 产品需求文档 (PRD)

## 目标和背景

### 目标
- 创建功能完整的全栈自我追踪应用，展示端到端现代开发实践
- 建立成本可控的架构，月运营成本控制在5美元以下，利用免费层服务
- 通过实际项目掌握集成技术栈（Docker、FastAPI、React、K3s、AWS、GitHub Actions）
- 开发基于矩阵的个人数据可视化系统，实现跨维度相关性分析
- 构建适合作品集展示的项目，体现真实世界开发技能和云部署专业能力
- 提供统一的个人数据管理解决方案，解决多平台数据分散问题

### 背景

LiVin Matrix 解决了理论学习与实际全栈开发经验之间的脱节问题。当前的教育资源提供孤立的技术演示，但缺乏端到端的项目集成，特别是涉及成本优化和生产部署考量的真实约束条件。

该项目同时解决个人数据管理问题，通过创建"矩阵化"方法来组织生活维度（睡眠、饮食、运动、情绪、生产力、社交）。与现有的单一功能追踪应用或浅层聚合平台不同，LiVin Matrix 通过直观的跨维度相关性发现提供分析深度，在经过验证的量化自我市场中占据独特定位。

## 需求

### 功能需求

**FR1:** 系统支持用户注册和登录，集成GitHub OAuth实现零成本安全认证
**FR2:** 用户可以记录固定的6个核心维度数据（睡眠、饮食、运动、情绪、工作效率、社交）
**FR3:** 系统提供快速数据录入界面，用户可在2分钟内完成日常数据输入
**FR4:** 用户可以查看交叉关系矩阵，展示不同维度间的相关性热力图
**FR5:** 系统支持按日/周/月查看数据模式和趋势分析
**FR6:** 用户可以点击矩阵单元格查看详细数据和钻取分析
**FR7:** 系统计算统计学显著的维度间相关性（皮尔逊相关系数）
**FR8:** 用户可以导出完整数据为CSV和JSON格式
**FR9:** 系统识别和高亮显示异常数据点供用户分析
**FR10:** 用户可以回溯修改历史记录数据
**FR11:** ~~系统支持标准CSV格式的批量数据导入功能~~ (移至未来MVP)
**FR12:** 系统提供自动化数据备份机制，支持用户手动触发备份

### 非功能需求

**NFR1:** 系统月运营成本必须控制在5美元以下，充分利用AWS免费层
**NFR2:** 页面加载时间首次小于3秒，后续导航小于1秒  
**NFR3:** 数据查询响应时间单维度小于500ms，矩阵分析小于2秒
**NFR4:** 系统支持至少10个并发用户访问
**NFR5:** 所有用户数据实现完全隔离，确保数据安全
**NFR6:** 系统实现零数据丢失，所有操作有事务保护
**NFR7:** 支持响应式设计，适配桌面和平板设备
**NFR8:** 系统架构必须展示Docker容器化、K3s编排、GitHub Actions CI/CD的完整集成
**NFR9:** 代码测试覆盖率达到80%以上，具备完整的API文档

## 用户界面设计目标

### 整体UX愿景

LiVin Matrix 采用**简洁数据导向的设计风格**，通过深色背景和青绿色调营造专业的数据分析氛围。界面设计强调**数据可视化的直观性和功能可用性**，让复杂的跨维度关系通过简洁清晰的矩阵热力图一目了然。

核心设计理念：让用户专注于数据洞察而非视觉效果，优先保证功能完整性和使用效率。

### 关键交互范式

- **矩阵式导航：** 主要交互通过点击矩阵单元格实现数据钻取和切换
- **简洁反馈：** 支持鼠标悬停高亮、点击展开详情的基础交互
- **键盘优化：** 数据录入支持Tab键快速切换，Enter键提交，ESC键取消
- **响应式布局：** 桌面端优先的矩阵视图，平板端简化为列表+图表模式

### 核心屏幕和视图

**主仪表盘（Dashboard）** - 展示关键指标概览和最新数据状态
**矩阵分析视图（Matrix View）** - 核心功能，展示跨维度相关性热力图（使用Recharts实现）
**数据录入页面（Data Entry）** - 简洁的表单界面，支持快速日常录入
**趋势分析页面（Trends）** - 时间序列图表和统计分析结果
**个人资料设置（Profile）** - 用户信息、数据偏好和隐私控制
**数据管理页面（Data Management）** - 导入/导出、备份和历史数据编辑

### 可访问性：WCAG AA

遵循WCAG AA标准，确保色盲用户可以通过图案纹理区分矩阵数据，键盘用户可以完全操作所有功能，屏幕阅读器用户可以获得完整的数据信息。

### 品牌风格

**简洁数据导向风格：** 深色主题配合青绿色调，强调数据可读性和功能实用性。采用清晰的几何线条，等宽字体体现技术感，避免装饰性动画效果。

设计灵感：现代数据分析工具的专业性 + 暗色主题的舒适感。

### 目标设备和平台：Web响应式

**主要支持：** 1024px以上桌面端，完整矩阵视图和分析功能
**次要支持：** 768px以上平板端，简化的列表视图和基础图表
**不支持：** 手机端复杂矩阵交互（MVP阶段暂不考虑）

## 技术假设

### 仓库结构：Monorepo

单一仓库便于管理前后端代码同步，简化CI/CD流水线配置，适合个人项目的开发和维护节奏。

### 服务架构

**单体应用架构（前后端分离）**
- 前端：React应用部署到GitHub Pages
- 后端：FastAPI应用运行在AWS EKS/K3s集群
- 数据库：AWS RDS PostgreSQL独立服务

选择理由：避免微服务的复杂性，但保持前后端技术栈的独立性，便于学习和展示不同技术能力。

### 测试要求

**Unit + Integration测试策略**
- 前端：Jest + React Testing Library，组件级和集成测试
- 后端：pytest + FastAPI TestClient，API端点和业务逻辑测试
- 目标覆盖率：80%以上（符合NFR9要求）

选择理由：不实施复杂的端到端测试，重点保证核心功能的单元测试和API集成测试质量。

### 其他技术假设和决策

**前端技术栈：**
- **React 18+ + TypeScript** - 现代前端开发标准，强类型支持
- **Tailwind CSS** - 快速样式开发，简洁的深色主题实现
- **Recharts（简化配置）** - 数据可视化库，专注基础矩阵热力图
- **React Hook Form** - 表单管理，优化数据录入体验
- **React Context + useReducer** - 状态管理，避免Redux复杂性

**后端技术栈：**
- **FastAPI + Pydantic** - 现代Python web框架，自动API文档生成
- **SQLAlchemy ORM + Alembic** - 数据库抽象和版本控制
- **Auth0集成** - 外部认证服务，避免自建认证复杂性
- **pytest测试框架** - Python标准测试工具

**基础设施选择：**
- **Docker + Docker Compose** - 开发环境一致性
- **K3s轻量级编排** - 学习容器编排，比K8s简单
- **GitHub Actions** - CI/CD自动化，代码到生产流水线
- **AWS免费层服务组合** - EKS + RDS + S3，零成本运营

**关键技术决策权衡：**
- 选择K3s而非原生K8s，降低学习难度但保持容器编排核心概念
- 选择Auth0而非自建认证，节省开发时间专注核心业务逻辑
- 选择简化的Recharts配置，优先功能完整性避免过度工程化
- 选择PostgreSQL单机部署，避免数据库集群复杂性满足个人使用需求

**维护成本预估：**
项目完成后第1年维护投入约80-100小时，后续年均30-40小时，主要集中在AWS服务管理、CI/CD维护和数据可视化优化。

### 核心维度详细定义

**1. 睡眠维度 (Sleep)**
- 睡觉时间段: 23:00 → 07:30 (时间选择器)
- 睡眠质量: 1-10分主观评分
- 晨起清醒度: 1-10分主观评分

**2. 饮食维度 (Nutrition)**
- 总热量: kcal (整数)
- 蛋白质: 克 (整数)
- 脂肪: 克 (整数)
- 碳水化合物: 克 (整数)

**3. 运动维度 (Exercise)**
- 总训练时长: 分钟 (自动累计)
- 今日步数: 千步 (如8.5)

*分时段训练记录 (可多次):*
- **力量训练**: 开始/结束时间、训练强度(1-10)、练后感受(1-10)
- **有氧训练**: 开始/结束时间、有氧类型(跑步/骑行/游泳/HIIT/器械/其他)、训练强度(1-10)、练后感受(1-10)

**4. 情绪维度 (Mood)**
- 整体心情: 1-10分主观评分
- 压力感: 1-10分主观评分
- 焦虑程度: 1-10分主观评分
- 精力水平: 1-10分主观评分

**5. 工作效率维度 (Productivity)**
- 深度工作时长: 小时 (可含小数)
- 主动休息次数: 整数
- 专注质量: 1-10分主观评分
- 任务完成度: 1-10分主观评分
- 工作满意度: 1-10分主观评分
- 工作环境: 家中/办公室/咖啡厅/混合 (单选)

**6. 社交维度 (Social)**
- 发起社交次数: 整数 (主动联系别人的次数)
- 响应社交次数: 整数 (回应别人联系的次数)
- 人际满意度: 1-10分主观评分
- 独处满足度: 1-10分主观评分

### 数据录入用户流程

**录入目标**: 3-4分钟完成所有6个维度
**设计原则**: 简单、快速、直观、容错

**流程设计:**
1. **单页面6个折叠卡片布局**: 用户可以按任意顺序完成各维度录入
2. **智能默认值**: 基于历史数据预填充常用数值
3. **快捷操作**: 支持键盘导航、一键模板、批量操作
4. **容错机制**: 自动保存草稿、数据验证提醒、允许跳过和后续补充
5. **进度可视化**: 实时显示完成度和预计剩余时间

**录入时间分配:**
- 睡眠维度: 30秒 (时间选择器 + 星级评分)
- 饮食维度: 45秒 (数值输入 + 快速模板)
- 运动维度: 60-90秒 (分时段训练记录)
- 情绪维度: 30秒 (4个星级评分)
- 工作效率维度: 45秒 (数值 + 评分 + 环境选择)
- 社交维度: 30秒 (计数 + 星级评分)
