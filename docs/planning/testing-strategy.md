# LiVin Matrix 测试策略

## 核心哲学

### 质量驱动开发

测试策略服务于**80%覆盖率**的质量标准，确保每个组件、Hook和业务逻辑都有可靠的测试保障。测试不是开发的负担，而是代码质量和重构信心的基础。

### 分层测试架构

采用测试金字塔策略：大量单元测试作为基础，适量集成测试保障协作，少量E2E测试覆盖关键用户流程。

---

## 测试分层策略

### 单元测试层 (70%比重)
**覆盖范围**:
- 所有UI组件的渲染和交互逻辑
- 自定义Hook函数的状态管理逻辑
- 工具函数的输入输出验证
- 状态管理的reducer和action处理

**技术栈**: Jest + React Testing Library
**覆盖率要求**: ≥80% (branches/functions/lines/statements)

### 集成测试层 (25%比重)
**覆盖范围**:
- 页面组件的完整渲染和数据流
- API层与前端状态的集成
- 路由导航和页面间状态传递
- 表单提交的完整数据流程

**技术栈**: Jest + React Testing Library + MSW (Mock Service Worker)

### 端到端测试层 (5%比重)
**关键用户流程**:
- 用户注册登录完整流程
- 6维度数据录入完整流程
- 矩阵分析交互和数据钻取
- 响应式设备适配验证
- 无障碍功能键盘导航

**技术栈**: Playwright或Cypress (按需选择)

---

## 测试质量标准

### 覆盖率要求
**最低标准**: 80%覆盖率（branches/functions/lines/statements）
**核心组件**: 90%+覆盖率（MatrixHeatmap、DataEntryForm、Dashboard）
**工具函数**: 100%覆盖率（纯函数易测试）

### 测试可读性
- **AAA模式**: Arrange → Act → Assert清晰结构
- **描述性命名**: 测试名称描述预期行为，不是实现细节
- **Mock策略**: 适度Mock外部依赖，保持测试独立性

### 性能要求
- **单元测试**: 平均<10ms/测试，快速反馈循环
- **集成测试**: <100ms/测试，可接受的CI时间
- **E2E测试**: <30秒/流程，关键路径验证

## 关键组件测试策略

- 异步状态更新

**测试重点**:

- 错误状态展示
- 键盘导航和无障碍

## CI/CD集成

### 测试门禁
- **Pre-commit**: 运行单元测试，阻止破坏性提交
- **PR验证**: 完整测试套件，覆盖率报告
- **部署前**: E2E测试验证关键流程

### 测试报告
- **覆盖率趋势**: 跟踪测试覆盖率变化
- **性能监控**: 测试执行时间趋势
- **失败分析**: 自动化失败原因分类

---

**测试策略是代码质量的基石，为重构和功能扩展提供信心保障。每个测试都应该有明确的价值和目的。**
