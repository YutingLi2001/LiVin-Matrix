# LiVin Matrix 集成架构

## 核心哲学

### 数据流优先

集成架构围绕6维度数据的完整生命周期设计：录入 → 验证 → 存储 → 分析 → 可视化。每个集成决策都要回答：它是否优化了用户数据从输入到洞察的流程效率？

### API契约驱动

前后端协作基于严格的API契约。FastAPI自动生成OpenAPI规范，TypeScript + Pydantic确保类型安全一致性，避免前后端集成的沟通成本。

### 零延迟体验

在成本约束下最大化响应速度。5分钟TTL智能缓存、异步处理架构、本地状态管理，确保用户操作的即时反馈。

---

## API架构设计

### RESTful设计原理

**统一资源标识**
- `/api/v1/auth/*` — 认证相关操作
- `/api/v1/dimensions/*` — 维度数据管理
- `/api/v1/matrix/*` — 矩阵分析接口
- `/api/v1/users/*` — 用户信息管理

**HTTP语义化**
- GET查询数据，POST创建资源，PUT完整更新，PATCH部分更新
- 状态码语义明确：200成功，201创建，401未认证，422验证失败

**统一响应格式**
- **结构化响应** — 成功状态、数据负载、错误信息、元数据的标准结构
- **类型安全** — 基于泛型的响应类型，确保前后端类型一致性
- **错误处理** — 统一的错误码体系和人性化错误信息

### 版本化策略

**URL路径版本化** — `/api/v1/`前缀确保向后兼容性
**渐进迁移** — 新版本至少保留旧版本6个月，通过`X-API-Deprecated`头标记弃用
**文档同步** — 每个版本独立的OpenAPI文档，自动生成和更新

### 认证集成

**认证集成架构**
- **双重认证模式** — GitHub OAuth外部认证 + JWT内部令牌管理
- **无状态设计** — JWT令牌携带完整认证信息，支持分布式部署
- **安全撤销机制** — 黑名单模式确保令牌可控撤销

## 数据流架构

### 6维度数据处理管道

**数据处理架构**
- **多层验证** — 客户端和服务端的双重数据验证保障
- **事务保护** — 数据操作的ACID特性确保一致性
- **异步处理** — 分析计算与用户交互的分离，提升响应速度

**处理策略**
- **输入验证** — 客户端基础验证 + 服务端业务逻辑验证双重保障
- **数据转换** — Pydantic模型确保数据格式一致性
- **存储优化** — PostgreSQL关系模型支持复杂查询和数据完整性
- **分析计算** — 皮尔逊相关系数算法，支持滑动窗口分析

### 相关性分析数据流

**智能计算策略**
- **批处理模式** — 定期全量相关性分析
- **增量更新** — 新数据录入时触发增量计算
- **并行处理** — 6x6矩阵相关性并行计算优化
- **结果缓存** — Redis缓存分析结果，5分钟TTL平衡性能和实时性

### 状态同步机制

**前后端状态一致性**
- **Context管理** — React Context + useReducer全局状态
- **本地持久化** — localStorage存储用户偏好，sessionStorage临时数据
- **React Query** — 服务端状态管理，支持缓存、重试、背景更新
- **缓存策略** — 智能缓存减少API调用，数据变更时自动同步
- **Resend集成** — 邮件服务API，支持用户通知和数据导出
