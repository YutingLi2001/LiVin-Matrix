# LiVin Matrix 安全架构

## 核心哲学

### 安全即成本优化

安全架构围绕零成本约束设计。从Auth0 ($35/月) 迁移到GitHub OAuth + 自建JWT ($0/月) 证明了一个原理：成本约束可以推动更安全、更自主的架构选择。

### 深度防护

多层次安全策略：网络层的HTTPS和代理隔离、应用层的JWT认证和输入验证、数据层的加密存储和访问控制、基础设施层的容器隔离和密钥管理。

### 隐私即设计

6维度个人数据的收集、存储、处理全程遵循隐私保护原则。用户完全拥有数据控制权，支持无损导出和完整删除。

## 密钥管理架构

### Docker Secrets策略

**企业级密钥管理**
- **加密存储** — Docker内置加密机制保护所有敏感密钥
- **访问控制** — 基于容器级隔离，只有指定服务能访问对应密钥
- **审计跟踪** — 完整的密钥访问日志和操作记录
- **零明文暴露** — 彻底消除环境变量和配置文件的明文存储风险

**四个核心密钥管理**
- **GitHub OAuth密钥** — 用户认证的核心凭据
- **JWT签名密钥** — 令牌生成和验证的加密基础
- **数据库密码** — PostgreSQL访问的安全凭据
- **会话密钥** — FastAPI会话管理的加密基础

**多环境策略**
- **开发环境** — 本地密钥文件 + chmod 600权限保护
- **生产环境** — Docker Swarm Secrets + 分布式加密存储
- **双模式支持** — SecretsService自动检测并回退到环境变量

### 密钥生命周期管理

**生成与分发**
- 强随机密钥生成算法
- 安全的密钥分发机制
- 环境间密钥隔离

**轮换与撤销**
- 密钥定期轮换策略 (建议每6个月)
- 即时撤销和黑名单机制
- 零停机密钥更新

### CI/CD密钥管理策略

**GitHub Secrets集成**
- **命名一致性** — GitHub Repository Secrets与Docker Secrets完全对应
- **环境隔离** — 开发/测试/生产环境密钥严格分离
- **最小权限** — CI/CD流水线只访问必需的密钥集合
- **审计追踪** — 所有密钥使用都有完整的日志记录

**密钥安全原则**
- **强密码要求** — 所有密钥使用加密安全的随机值生成
- **零暴露策略** — 严禁在日志、代码、配置中暴露密钥明文
- **访问控制** — 基于角色的密钥访问权限管理
- **定期轮换** — 建立密钥轮换提醒和自动化机制

## 认证授权架构

### GitHub OAuth + JWT双重认证

**OAuth认证流程**
1. 用户点击GitHub登录 → 重定向到GitHub授权页面
2. 用户授权 → GitHub返回授权码
3. 后端交换access_token → 获取用户信息
4. 创建/更新用户记录 → 生成JWT令牌

**JWT令牌安全机制**
- **HS256算法** — 对称加密，适合单体应用架构
- **24小时过期** — 平衡安全性与用户体验
- **JTI唯一标识** — 每个令牌的唯一追踪标识符
- **黑名单机制** — 支持令牌即时撤销和登出

**会话管理策略**
- **多设备支持** — 用户可在多个设备同时登录
- **静默续期** — 接近过期时自动刷新令牌
- **安全登出** — 令牌加入黑名单，确保彻底失效

### API认证集成

**中间件认证**
- JWT Bearer令牌验证
- 自动用户身份提取
- 细粒度权限控制

**CSRF保护**
- OAuth state参数验证
- 安全的跨域请求处理
- 防止请求伪造攻击
