# LiVin Matrix 基础设施架构

## 核心哲学

### 免费层最大化

基础设施设计围绕AWS免费Tier资源的极限利用。EKS控制平面免费、t3.micro实例750小时/月、RDS 20GB存储，每个选择都要回答：它是否最大化免费资源的价值？

### 简洁性胜过高可用

在零成本约束下，选择单AZ部署和简化架构胜过复杂的高可用性方案。可靠性通过健康检查、自动恢复和快速部署来保障。

### 云原生实践

采用EKS Kubernetes、容器化部署、基础设施即代码等现代云原生实践。成本约束不意味着技术落后，而是在约束中探索最佳实践。

## AWS资源架构

### 计算资源规划

**EKS Kubernetes集群**
- **控制平面** — 完全免费，AWS托管的Kubernetes API服务器
- **工作节点** — 2个t3.micro实例（750小时/月免费额度）
- **自动扩缩容** — 根据负载动态调整节点数量，最小1个最大3个
- **实例优化** — 最小化资源配置，专注核心功能

**Lambda函数备用**
- **无服务器补充** — 100万次请求/月免费额度
- **定时任务** — 数据分析、清理任务的备选方案
- **Nginx反向代理** — 静态文件服务和API代理
- **Redis缓存** — 6.2版本，session和分析结果缓存
- **成本控制** — 在EC2资源不足时的弹性扩展

### 存储资源设计

**RDS PostgreSQL数据库**
- **实例规格** — db.t3.micro（750小时/月免费）
- **存储配置** — 20GB通用SSD，启用自动扩展至50GB
- **备份策略** — 7天自动备份，凌晨3-4点备份窗口
- **加密保护** — 静态数据加密，传输加密

**S3对象存储**
- **标准存储** — 5GB免费存储空间
- **数据备份** — 数据库备份和配置文件存储
- **静态资源** — 前端资源的备选CDN源

**EBS块存储**
- **通用SSD** — 30GB/月免费额度
- **持久化卷** — Kubernetes有状态应用支持
- **快照策略** — 关键数据的定期快照备份

### 网络架构设计

**网络分层设计**
- **三层网络架构** — 公有子网承载负载均衡，私有子网运行应用，数据库子网隔离存储
- **跨可用区部署** — 多AZ分布提升可用性，平衡成本与稳定性
- **网络隔离策略** — 通过子网和安全组实现多层访问控制

**负载均衡策略**
- **Application Load Balancer** — 应用层负载均衡，支持SSL终端
- **健康检查** — 自动故障检测和流量转发
- **SSL证书** — Let's Encrypt免费证书，自动续期

**安全组配置**
- **最小权限原则** — 严格限制网络访问规则
- **分层防护** — ALB、EKS、RDS各层独立安全组
- **流量控制** — 仅允许必要的端口和协议通信

## 容器编排架构

### EKS vs K3s决策

**选择EKS的关键原因**
- **免费控制平面** — 避免自管理Kubernetes的运维成本
- **AWS原生集成** — ALB、EBS、IAM、CloudWatch的无缝集成
- **企业级管理** — 自动更新、安全补丁、监控告警
- **学习价值** — 现代云原生架构的完整体验

### 容器化最佳实践

**Docker镜像优化**
- **多阶段构建** — 分离构建环境和运行环境，减少镜像大小
- **非root用户** — 容器安全最佳实践
- **健康检查** — 完整的liveness和readiness探针配置
- **资源限制** — CPU和内存请求/限制的精确配置

**服务发现和网络**
- **Kubernetes DNS** — 集群内服务自动发现
- **VPC CNI插件** — 原生AWS网络集成
- **Network Policy** — 微分段网络安全策略
- **Service Mesh** — 未来考虑istio集成

### 数据持久化策略

**有状态服务支持**
- **PersistentVolume** — EBS卷的自动配置和管理
- **StatefulSet** — 有状态应用的部署和扩展
- **数据备份** — 卷快照和跨AZ复制
