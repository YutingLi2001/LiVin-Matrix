# ADR-001: 服务启动方式标准化

## 状态
已实施 - 2025-08-05

## 背景
项目存在7种不同的启动模式，造成开发环境不一致和安全风险。具体问题包括：

- 进程管理不稳定：命令行会话依赖导致服务超时终止
- 启动流程不标准化：手动启动导致环境不一致
- Agent启动服务不规范：缺乏标准化约束，创建临时文件和secret暴露
- 严重安全风险：硬编码密码、明文API密钥、多套不协调的密钥管理系统
- 配置混乱：7种启动方式（3种Docker Compose变体、Scripts/Services、Scripts/Dev、Backend内部脚本、文档临时方式）

## 决策
采用`scripts/services/` Command脚本 + Docker Secrets作为唯一标准启动方式：

- 统一启动入口点：`./scripts/services/start-all.command`
- 生产级密钥安全管理：完全使用Docker Secrets，消除所有.env文件
- 开发环境与生产环境配置一致性
- 完整的环境检查、健康监控和故障排除能力

## 替代方案
**保持现状** - 被拒绝：安全风险过高，开发效率低下

**仅Docker Compose标准化** - 被拒绝：缺乏环境检查和依赖管理

**混合启动方式** - 被拒绝：仍然存在不一致性问题

## 结果
- 消除了6种冗余启动方式，建立单一标准流程
- 实现零明文密钥文件，所有敏感信息使用Docker Secrets管理
- 提供双击启动、自动验证、智能错误处理的用户体验
- 建立了完整的故障排除和服务监控机制
- 为Epic 1.5的人类操作任务集成奠定了基础
