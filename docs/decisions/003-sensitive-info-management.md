# ADR-003: 敏感信息管理策略

## 状态
已实施 - 2025-08-04

## 背景
项目作为公开repository面临严重的敏感信息泄露风险。原有的.env文件管理方式存在多重安全隐患：

- 数据库密码、API密钥等敏感信息存在误提交风险
- AI Agent启动服务时创建临时文件，导致secret暴露
- 多套不协调的密钥管理系统并存，配置管理混乱
- 不同开发者环境配置不一致，难以复现问题

## 决策
采用分层敏感信息管理策略：

- **本地开发**: 使用Docker Secrets管理所有敏感信息
- **CI/CD**: 使用GitHub Repository Secrets
- **配置模板**: 创建.env.template替代实际.env文件的版本控制
- **自动化设置**: 提供setup-env.sh脚本引导环境配置
- **完善.gitignore**: 严格排除所有敏感文件类型

核心原则：零敏感信息进入版本控制，统一的Secret管理机制。

## 替代方案
**继续使用.env文件** - 被拒绝：高误提交风险，无法满足公开repository安全要求

**环境变量注入** - 被拒绝：进程列表中敏感信息可见，开发环境配置复杂

**外部配置服务** - 被拒绝：增加系统复杂度和成本，不符合零成本目标

## 结果
- 完全消除版本控制中的敏感数据泄露风险
- 建立标准化的环境配置和启动流程
- 实现开发、测试、生产环境的配置一致性
- 提供Docker Secrets的容器级访问控制和GitHub Secrets的集中管理
- 为Epic 1.5的标准化启动流程奠定了安全基础
