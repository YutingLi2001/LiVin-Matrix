# Project Brief: LiVin Matrix

## Executive Summary

**LiVin Matrix** 是一个教育导向的全栈自我追踪web应用，旨在为开发者提供使用现代工具链（Docker、FastAPI、AWS、K3s、GitHub Actions）构建完整产品的实践经验。该项目通过"矩阵化"方式组织个人生活数据（睡眠、饮食、运动、情绪、生产力等），展示如何在严格的成本约束下（<$5/月运营成本）构建可扩展的数据分析平台。

**主要目标：** 创建一个功能完整的自我追踪应用，同时最大化学习价值和最小化运营成本，展示现代免费服务生态系统的能力。

**目标用户：** 主要是项目创建者本人，次要是希望学习全栈开发和成本优化技术的其他开发者。

**核心价值：** 提供真实世界的项目开发体验，展示如何使用免费/低成本服务构建生产级应用，同时获得个人数据洞察。

LiVin Matrix positioned itself in the validated quantified self market by bridging the gap between narrow single-purpose tracking apps (like MyFitnessPal) and broad but shallow health platforms (like Apple Health). Unlike existing solutions that either focus on one dimension or provide superficial integration, LiVin Matrix offers the analytical depth that data-driven users crave with the holistic view they need, organized through an intuitive matrix interface that makes complex correlations discoverable.

## Problem Statement

**当前状态和痛点：**

作为开发者，在学习现代全栈开发时面临以下挑战：
- **理论与实践脱节：** 大多数教程和课程提供孤立的技术演示，缺乏端到端的真实项目体验
- **工具链集成复杂性：** Docker、K3s、AWS、CI/CD等工具单独学习容易，但整合使用时会遇到实际的配置和集成问题
- **成本控制学习缺失：** 很少有资源教授如何在严格预算约束下构建生产级应用
- **个人数据分散问题：** 同时，作为用户，个人生活数据分散在多个平台上，难以获得整体洞察

**问题的影响（量化）：**
- **学习成本：** 开发者需要花费大量时间在多个分离的项目中才能掌握完整的技术栈
- **实践机会稀缺：** 缺乏真实的、有约束条件的项目来验证所学技能
- **成本意识不足：** 很多开发者第一次部署应用时会因为不了解云服务计费而产生意外高额费用

**现有解决方案的不足：**
- **传统教程项目：** 通常忽略成本优化、生产部署、监控等实际考量
- **开源个人项目：** 大多关注单一技术点，缺乏系统性的技术栈演示
- **商业化self-tracking应用：** 不开源，无法学习架构和实现细节

**为什么现在解决这个问题很重要：**
- **云原生技术成为标准：** K3s、容器化等技能现在是必需的，不是可选的
- **成本意识日益重要：** 经济环境下，优化资源使用成为核心技能
- **个人项目作为求职敲门砖：** 雇主越来越看重实际项目经验而非仅仅是算法题

现有的问题陈述应该更明确地体现这些约束不是障碍，而是有价值的学习条件。真实世界的项目总是在约束下进行的，学会在限制中创造价值是核心技能。

## Proposed Solution

**核心概念和方法：**

LiVin Matrix 采用"矩阵化数据组织"的概念，将个人生活的关键维度（睡眠、饮食、运动、情绪、生产力等）作为矩阵的行和列，通过交叉分析发现生活模式和相关性。解决方案包括三个核心层次：

**1. 数据收集层**
- 简洁的手动输入界面，支持快速记录多维度数据
- 标准化的数据导入/导出功能，确保数据便携性
- 灵活的数据模型，支持用户自定义追踪维度

**2. 分析处理层**
- 基础统计分析：趋势、平均值、波动性
- 相关性分析：发现不同维度间的潜在联系
- 矩阵可视化：直观展示多维度数据关系

**3. 洞察展示层**
- 个性化仪表盘，展示关键指标和趋势
- 交互式矩阵视图，支持数据钻取和筛选
- 简单的报告生成，便于长期追踪

**关键差异化优势：**

**vs 单一维度应用：** 通过矩阵组织实现全局视角，发现跨维度相关性
**vs 复杂分析工具：** 保持用户友好的同时提供深度洞察
**vs 商业化平台：** 完全透明的开源架构，无数据锁定，成本可控

**技术实现高层愿景：**

- **前端：** React/Vue + 现代图表库，实现响应式矩阵界面
- **后端：** FastAPI + PostgreSQL，提供RESTful API和数据持久化
- **部署：** Docker容器化 + K3s编排，实现自动化部署和扩展
- **CI/CD：** GitHub Actions实现代码到生产的完整流水线
- **基础设施：** AWS免费tier服务，严格控制运营成本

**为什么这个解决方案会成功：**

1. **学习价值最大化：** 涵盖现代全栈开发的所有核心环节
2. **实用性保证：** 解决真实的个人数据管理需求
3. **约束驱动创新：** 成本和时间限制促进最佳实践学习
4. **可复制性：** 其他开发者可以基于此项目学习和扩展

## MVP Scope

### Core Features (Must Have)

**1. 用户认证与账户管理**
- **用户注册/登录：** 集成Auth0实现安全认证，支持邮箱注册
- **个人资料设置：** 基础用户信息管理，时区设置，数据偏好配置
- **数据隐私控制：** 用户完全控制自己的数据，支持账户删除

**2. 数据录入系统**
- **多维度数据录入：** 支持至少6个核心维度（睡眠、饮食、运动、情绪、工作效率、社交）
- **快速录入界面：** 简洁的表单设计，2分钟内完成日常数据录入
- **数据验证：** 输入数据的合理性检查和格式标准化
- **历史数据编辑：** 支持回溯修改历史记录

**3. 矩阵可视化核心**
- **交叉关系矩阵：** 展示不同维度间的相关性热力图
- **时间维度切片：** 按日/周/月查看数据模式
- **数据点钻取：** 点击矩阵单元格查看详细数据和趋势
- **自定义维度组合：** 用户可选择显示哪些维度的交叉分析

**4. 基础分析功能**
- **趋势分析：** 各维度的时间序列图表和趋势线
- **相关性计算：** 统计学显著性检验（皮尔逊相关系数）
- **异常检测：** 识别和高亮显示偏离正常模式的数据点
- **周期性模式：** 工作日vs周末，月度周期等模式识别

**5. 数据管理**
- **数据导出：** 支持CSV、JSON格式的完整数据导出
- **数据备份：** 自动化数据备份机制
- **简单导入：** 支持标准CSV格式的批量数据导入

## Technical Considerations

### Platform Requirements

**目标平台：**
- **Web应用优先：** 响应式设计，支持桌面和平板访问
- **浏览器支持：** Chrome、Firefox、Safari、Edge现代版本
- **设备适配：** 1024px+桌面端优化，768px+平板基础支持

**性能要求：**
- **页面加载时间：** 首次加载 < 3秒，后续导航 < 1秒
- **数据处理能力：** 支持单用户1年+的历史数据查询分析
- **并发用户：** 设计支持10个并发用户（个人项目足够）

### Technology Preferences

**前端技术栈：**
- **框架：** React 18+ + TypeScript (学习现代前端开发标准)
- **UI库：** Tailwind CSS + 自定义赛博朋克主题 (快速开发，现代设计)
- **图表库：** Recharts (矩阵可视化和数据图表，支持深度定制)
- **状态管理：** React Context + useReducer (避免Redux复杂性)
- **图标库：** Lucide React (简洁稳定的图标库)
- **表单处理：** React Hook Form (成熟稳定的表单管理)
- **动画库：** Framer Motion (渐进式引入，从简单效果开始)

**后端技术栈：**
- **API框架：** FastAPI (现代Python web框架，自动API文档)
- **数据控制：** SQLAlchemy ORM (数据库抽象，支持迁移)
- **认证服务：** Auth0 (避免自建认证系统复杂性)
- **数据验证：** Pydantic (类型安全，自动验证)

**数据库：**
- **主数据库：** PostgreSQL 13+ (关系型数据，支持JSON字段)
- **数据迁移：** Alembic (版本控制数据库schema变更)

**基础设施（零成本方案）：**
- **前端托管：** GitHub Pages (免费静态网站托管)
- **后端部署：** AWS API Gateway + EKS (免费tier)
- **容器化：** Docker + Docker Compose (开发环境一致性)
- **编排：** K3s (轻量Kubernetes，学习容器编排)
- **云服务：** AWS免费tier (EKS + RDS + S3)
- **CI/CD：** GitHub Actions (代码到生产的自动化流水线)

**服务架构：**
- **单体应用架构：** 前后端分离但部署在同一集群内
- **API设计：** RESTful API，OpenAPI 3.0文档自动生成
- **数据库连接：** 连接池管理，支持读写分离(可选)

**集成需求：**
- **认证流程：** Auth0 JWT token验证，支持refresh token
- **文件存储：** AWS S3用于数据导出文件和静态资源
- **监控日志：** 基础的应用日志，错误追踪

**安全合规：**
- **数据加密：** HTTPS传输，敏感数据数据库加密
- **访问控制：** 基于JWT的用户授权，API rate limiting
- **隐私保护：** 用户数据隔离，支持数据删除(GDPR compliance)
- **备份策略：** 自动化数据库备份到S3

### 数据库Schema设计

**基于二级结构的数据模型（无时间轴）：**
```sql
-- 数据维度分类表
categories (
  id SERIAL PRIMARY KEY,
  user_id INT,
  name VARCHAR(50),        -- "饮食", "饮水", "运动"等
  description TEXT,
  is_custom BOOLEAN,       -- 是否用户自定义
  created_at TIMESTAMP
);

-- 分类下的具体字段
category_fields (
  id SERIAL PRIMARY KEY,
  category_id INT REFERENCES categories(id),
  field_name VARCHAR(50),   -- "卡路里", "蛋白质", "总饮水量"等
  field_type VARCHAR(20),   -- "number", "time", "text"等
  unit VARCHAR(10),         -- "g", "ml", "小时"等
  is_required BOOLEAN,
  default_value TEXT
);

-- 用户数据记录（按日期汇总）
user_records (
  id SERIAL PRIMARY KEY,
  user_id INT,
  category_id INT REFERENCES categories(id),
  record_date DATE,
  field_values JSONB,      -- {"卡路里": 2000, "蛋白质": 120, "碳水": 250}
  created_at TIMESTAMP
);
```
